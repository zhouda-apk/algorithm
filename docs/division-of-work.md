# 四人分工與交接基準

2026-10-30，Phase 0。A～D 為職責代號，未取得真實姓名，不虛構人員；各組員認領代號即可開始。

| 角色 | 期中負責 | 交接物 |
| --- | --- | --- |
| A：整合 | 方案、csproj、共用契約、主控台入口、BenchmarkService、README | 可建置方案、操作流程與執行管線 |
| B：案例與保存 | DataGenerator、TestCaseService、JSON DTO、共享 JsonDataStore、兩個 Repository | 可重開的案例／Run 保存、備份及錯誤處理 |

| D：驗收與呈現 | TestRunner、跨模組測試、UI 草圖、需求對照與展示文件 | 驗證證據、兩張草圖、類別圖、示範腳本 |

共用 Models／Contracts、所有專案檔及方案檔由 A 整合最後版本。B、C 先依 contracts.md 開發，新增或改動簽章時同步修改文件及呼叫端；不得自行複製相似模型。測試 Runner 由 D 維護，模組測試可由負責人提供。

新功能使用各自工作分支；交接前更新共同基線、建置 Debug／Release x64，列明測試結果。尚未設定遠端時以同一來源的本機副本交接，不假設遠端地址；不得傳送 bin／obj 或個人 store.json 作為原始碼版本。

Phase 0 提供可開啟的四專案方案與角色分配。本機建置證據不能代替其他三位組員的電腦確認；每位組員需依 README 實際開啟並建置後，留下自己的環境與結果。
