# 上台展示與彩排腳本

2026-10-30。建議 5～7 分鐘，使用 Release x64、不附加偵錯器。請先填妥簡報的組員姓名、班級及學號。

## 展示前

解壓 RC1，使用 runtime/Start-Demo.cmd 啟動獨立展示庫，該庫位於 LocalAppData/AlgorithmLab-MidtermDemo，不與一般 AlgorithmLab 正式資料混用。確認字體、投影、檔案權限及退出後重開；既有展示資料先在程式內檢視，不直接刪除檔案。

主控台選單數字以目前畫面為準；清單按更新時間排序，不假設特定名稱永遠是第 1 筆。

| 時間 | 操作 | 講解重點 |
| --- | --- | --- |
| 0:00～0:40 | 專題名稱、目的與期中／期末範圍 | 管理可重現案例、驗證排序、觀察時間與操作數 |
| 0:40～1:20 | 顯示類別圖並指認 TestCase／Service／ISortAlgorithm | 封裝資料副本、分層、介面、繼承及多型 |
| 1:20～2:10 | 主選單 1→案例選單 4，新增 Random，N=1000、範圍 -10000～10000、seed=42；確認 Y | 預覽後才保存，保存的是實際數值及生成參數 |
| 2:10～2:40 | 選單 5，只改名稱；0 返回、0 結束，再重開 | 名稱改變，資料及種子不變；JSON 持久化 |
| 2:40～4:00 | 主選單 2，選同一案例分別執行三個演算法 | 相同原始資料副本；1 預熱＋5 正式時間＋1 獨立 Analysis |
| 4:00～4:40 | 主選單 3，各篩選欄空白；輸入序號看細節 | 同一 InputHash、原始樣本、Frequency、環境版本及操作數 |
| 4:40～5:10 | 案例選單 6 刪除原案例，再查歷史 | 快照及樣本仍可追溯，已刪案例不使歷史消失 |
| 5:10～5:40 | 新增手動案例，輸入 1,,2，空白行結束 | 缺值清楚報錯，不保存半份資料，程式可繼續使用 |
| 5:40～6:30 | 展示 WinForms 草圖與期末安排 | 期中只有草圖；期末遷移 SQLite 並實作視窗、圖表及批次 |
| 6:30～7:00 | 說明測試、四人分工與待跨機簽核 | 區分已驗證、待驗證及選配，回答老師問題 |

時間為彩排目標，並非測試超時保證。可使用主選單 4 快速建立三個固定種子的展示案例，但仍應展示一次新增／確認流程。

## 取消與復原備用展示

取消：建立 Reversed 5000 筆案例，選 Bubble Sort 開始後按 Ctrl+C。預期返回選單並保存 Cancelled／USER_CANCELLED，沒有正式聚合成績。大部分小案例可能在按鍵前已完成；若已完成，就如實顯示 Completed，不宣稱取消成功。本機已另外用隔離 Windows CTRL_C_EVENT 驗證事件路徑。

備份復原只用獨立測試庫，先關閉程式並保存原檔。壞檔不會自動清空；有效備份會顯示時間與版次，B 才進行復原，並保存損毀原檔。不要為上台展示破壞平常使用的 JSON。

## 備用素材及故障處理

- 真實操作逐字紀錄：evidence/demo-transcript.txt；真實結果與全部原始樣本：evidence/demo-store.json。
- 簡報用實測摘要：evidence/results-table.md；圖表與主視窗草圖的示意數據不作實測證據。
- 找不到執行環境時使用原始操作紀錄與已保存結果說明，明確告知現場無法啟動，不將圖片當作當場實測。
- 空清單先新增案例；資料庫與圖表未在期中實作，介紹時使用期末規劃用語。

現有專案的專題介紹指南另有完整講稿及分工說明。跨機確認表見 acceptance-checklist.md。
